Internal AI Systems · Multi-Agent Issue Triage · Durable Session Architecture

During my Software Engineering Internship at Google Ads Infrastructure (Display & Video 360), I designed and built internal AI systems to automate software issue triage, enable durable collaborative debugging, organize recurring user feedback, and streamline engineering maintenance workflows.

Working on large-scale infrastructure required balancing automated intelligence with system reliability, state durability, and developer trust. Key milestones included:

  • Building a multi-agent Python and Go issue-triage system to automate symptom summarization and duplicate detection.
  • Implementing durable, shareable AI session state that preserves investigation context across service restarts and engineer handoffs.
  • Designing an LLM-powered feedback analysis pipeline to organize unstructured user feedback into stable, actionable issue clusters.
  • Modernizing legacy Java backend services, migrating AI workflows into reusable skills, and adding automated regression tests.

Multi-Agent Issue Triage Architecture

In large-scale production infrastructure, significant engineering overhead is spent manually inspecting newly filed bug tickets, parsing raw system logs, searching for duplicate reports, and drafting initial investigation plans.

To streamline this workflow, I developed a multi-agent triage pipeline built in Python and Go. When a new software issue is filed, specialized subagents process the incoming ticket concurrently:

  • Symptom Summarizer Agent: Parses raw stack traces and log outputs to generate concise technical summaries of the failure mode.
  • Duplicate Matching Agent: Queries existing issue databases to identify related or duplicate tickets, preventing redundant investigations.
  • Investigation Planning Agent: Drafts initial hypotheses, pinpoints relevant service components, and suggests immediate diagnostic steps for the on-call engineer.

This multi-agent approach significantly reduced initial triage latency and provided engineers with instant, actionable context upon ticket assignment.

Durable & Shareable AI Sessions

Standard LLM interaction workflows are often ephemeral. When a complex engineering investigation spans multiple days, or when backend service instances redeploy, conversational debugging context can be lost.

Key architecture features of the durable session persistence layer included:

  • State Serialization: Serializing active agent state, context windows, and tool execution history into a persistent storage layer.
  • Cross-Restart Continuity: Automatically restoring investigation state after backend service restarts or instance migrations.
  • Seamless Engineer Handoff: Enabling one engineer to share a live investigation session link with another team member, allowing them to inspect prior reasoning and take over without losing context.

Continuous User-Feedback Analysis Pipeline

During an internal BuildAI hackathon, I tackled a recurring product challenge: product and engineering teams receiving high volumes of unstructured user feedback, making manual theme identification tedious and inefficient.

I designed and built an LLM-powered feedback processing pipeline that:

  • Incremental Clustering: Automatically maps newly arriving user reports into stable, semantic issue clusters without creating duplicate or renamed themes.
  • Dynamic Re-Clustering & Splitting: Detects when reports have been grouped incorrectly and automatically splits or merges clusters as new feedback arrives.
  • Multimodal & Log Analysis: Integrates screenshot analysis and system log inspection to surface clearer, more actionable product feedback for engineering teams.

Backend Modernization & Skill Testing

After completing my core internship milestones ahead of schedule, I took on additional technical contributions focused on code health and long-term maintainability:

Reflection & Systems Insights

Building AI infrastructure inside Google Ads Infrastructure highlighted several essential lessons for developer tooling:

  • Durability is Essential for Trust: AI assistants are only as useful as their state persistence. Preserving context across restarts is critical for long-running engineering workflows.
  • Multi-Agent Specialization Wins: Dividing complex triage into specialized, single-responsibility agents yields far more predictable and accurate outputs than single-prompt LLMs.
  • Automated Testing Protects AI Quality: Robust regression testing is just as necessary for prompt-driven workflows as it is for traditional backend code.
